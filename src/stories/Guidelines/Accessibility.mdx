# Accessibility

O Model UI Kit segue princípios básicos de acessibilidade para garantir melhor experiência para todos os usuários.

---

## Objetivos

- Navegação por teclado
- Contraste adequado
- Estados visuais claros
- Compatibilidade com leitores de tela
- Semântica HTML adequada

## Focus Visible

Todos os componentes interativos devem possuir estado de foco visível.

```scss
:focus-visible {
  outline: 2px solid var(--ui-color-primary);
  outline-offset: 2px;
}
```

---

## Contraste

As cores devem manter boa legibilidade entre:

- Texto e fundo
- Estados de erro
- Estados de sucesso
- Estados desabilitados
- Elementos focados

Use o painel **Accessibility** do Storybook (addon `@storybook/addon-a11y`) para auditar cada story em tempo real.

---

## ARIA

Exemplos de uso:

```html
<button aria-label="Salvar">
  Salvar
</button>
```

```html
<div role="alert">
  Operação concluída com sucesso
</div>
```

```html
<nav aria-label="Paginação de resultados">
  <!-- ui-pagination -->
</nav>
```

```html
<table aria-label="Tabela de dados">
  <th aria-sort="ascending">…</th>
</table>
```

## Screen Readers

Boas práticas adotadas:

- Uso de HTML semântico
- Labels descritivas
- Hierarquia correta de títulos
- Feedbacks acessíveis (`aria-live`, `role="status"`)
- Botões com texto claro ou `aria-label`
- Regiões nomeadas (`nav`, `table`, accordion com `aria-expanded`)

## Testes de acessibilidade

### No Storybook (manual)

1. Abra uma story
2. Painel **Accessibility** → revisar violações e warnings
3. Teste tema claro e escuro (toolbar Themes)

Configuração global em `.storybook/preview.ts`:

```ts
a11y: { test: 'todo' }
```

### Testes automatizados (CI / local)

Com Storybook rodando:

```bash
npm run test-storybook
```

O Test Runner executa:

1. Funções `play` das stories (interação)
2. Auditoria **axe** em cada story (`.storybook/test-runner.ts` + `axe-playwright`)

Para pular a auditoria em uma story específica, adicione a tag `skip-a11y` no meta.

### Helpers de interação

`projects/ui-kit/src/lib/storybook/play.helpers.ts` valida roles e labels esperados (`button`, `navigation`, `table`, `checkbox`, etc.).

---

## Checklist por componente

Ao criar ou revisar um componente:

- [ ] Foco visível em todos os controles
- [ ] Nome acessível (texto visível ou `aria-label`)
- [ ] Estados comunicados (`aria-disabled`, `aria-expanded`, `aria-sort`, `aria-current`)
- [ ] Story **Playground completo** com função `play`
- [ ] Sem violações críticas no painel a11y
- [ ] Testado em tema claro e escuro
